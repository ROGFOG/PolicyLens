# Почему default-src недостаточно

В примере из README default-src разрешает свой источник, script-src также
разрешает inline-код, а object-src запрещает объекты. PolicyLens выдаёт шесть
замечаний: два о разрешении inline-кода, три об отсутствии base-uri,
frame-ancestors и form-action, ещё одно о настройке HSTS. Эти три CSP-директивы
требуют собственных значений. Для HSTS нужен контекст реального HTTPS-сервера.

## Путь данных

`src/analyze.ts` принимает строку. Если найдены знакомые заголовки, строки
разбираются в таблицу с несколькими значениями на ключ. Поэтому повторные CSP
сохраняются отдельно. Иначе весь ввод считается одной политикой.

Внутри политики текст делится по `;`. Повторная директива вызывает замечание,
но в таблице остаётся первое значение. Для script-элементов проверка ищет
script-src-elem, затем script-src, затем default-src. Для атрибутов порядок
такой же, но начинается с script-src-attr.

Функция возвращает замечания, число политик и число заголовков. `src/main.ts`
выводит их через textContent, фильтрует по важности и сохраняет тот же отчёт
в JSON. Правила можно запускать и проверять без DOM и сетевого доступа.

## Что проверяется на самой странице

Политики через запятую пока пропускаются. Отдельные CSP-заголовки разбираются
независимо, хотя браузер применяет их одновременно. Генерация nonce, совпадение
хешей и фактическое поведение страницы требуют запуска приложения. Report-Only
показывается отдельно от блокирующей политики.

Порядок наследования описан в [MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy).
Примеры повторных директив и наследования находятся в `test/analyze.test.ts`.
